Trash, redesigned

Shipped in 5.17 and verified on the phone, but the first version was laid out as a list of cards rather than as a statement. Three things to fix, one of them a defect: the amount runs flush to the screen edge because the row is missing the 15dp inset every other list gives it, each entry costs two rows instead of one, and every row carries its own blue action — so a screen of five deleted entries has five competing calls to action and no single one.

Option A · one statement line, expiry in the caption

The app's governing idea is that a row is a printed statement line — fixed pitch, amount flush right, hairline between entries. Trash has no reason to be an exception: the time it has left is just another thing the caption says, next to the category and the hour. The amount dims because it is not counted in any total, which is the same treatment an untagged row already gets.

Restoring moves to selection, the pattern Activity already uses for acting on many rows at once. One deleted entry and twelve are then the same gesture, and the screen has exactly one call to action instead of one per row.

What changes in the code

ChangeWhy
15dp inset on the row The defect. Every other caller passes Modifier.padding(horizontal = EDGE); Trash did not, so the amount column stopped lining up with every other screen.
Expiry into the caption One row per entry instead of two. Amber under 14 days, red under 3 — the same warning/negative pair the rest of the app uses, never colour alone: the words say it too.
Amount dimmed A deleted row is in no total. Activity already dims untagged rows for exactly this reason.
Restore by selection One accent action per screen rather than one per row, and putting four entries back becomes one gesture. Reuses Activity's selection bar rather than inventing a second pattern.
Date, not clock time "7:25 pm" for something deleted last week answers a question nobody asked. The day it happened is what places it.

Also wrong, and not a layout question

The delete confirmation still reads "It goes from both phones and cannot be brought back." That was true when it was written and is now false twice over — there is an Undo on the way out and thirty days in here. A confirmation that overstates the damage is the kind of thing people learn to click through.
